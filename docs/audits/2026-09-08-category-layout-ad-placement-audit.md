# 分類頁版面與廣告位稽核

最後更新：2026-09-08

實作狀態：分類頁頂部 `category_after_intro` 已停用；901–1279px 已改為單欄並隱藏側欄；Inline 間隔已改由 `/admin/ads` 的 OWNER 設定控制（4–20，預設 10），且僅在後方仍有已載入文章時插入。

## 稽核範圍

- A：`/zh-tw/category/software`
- B：`/zh-tw/category/social`
- C：`/zh-tw/category/ai`
- 桌面視窗：約 1229 × 1104
- 使用者目標：進入分類後快速確認主題，並看到可閱讀的第一篇文章；廣告不應讓頁面看起來空白或故障。

## 整體結論

B 的無廣告狀態最接近合理的內容優先版面。A、C 同時出現頂部廣告與右側欄預留位，首篇文章被推到首屏底部；其中側欄在 901–1279px 是確定的斷點錯配，不會初始化廣告卻仍佔版面。建議先修正斷點，再取消分類頁頂部大型廣告，將主要收益版位移到文章列表中與真正可用的桌面側欄。

## 畫面步驟與健康度

1. **A／軟體教學：需改善** — 標題與說明清楚，但頂部廣告造成大段空白，第一篇文章幾乎落到首屏之外；右側另有不會初始化的空廣告位。
2. **B／社群平台：良好但內容偏少** — 沒有廣告時，標題、首篇文章與頁尾在同一視野內，閱讀路徑清楚。短分類不投放廣告的門檻合理。
3. **C／AI 教學：需改善** — 問題與 A 相同；首篇雖有封面，仍被廣告區推到首屏底部，內容價值出現太晚。

## 優點

- 三頁的麵包屑、唯一 H1、分類說明與文章 H2 層級一致。
- 文章列表使用有序清單，卡片標題、摘要、日期與「閱讀解答」的資訊結構清楚。
- 文章卡片和背景的色彩、圓角、間距一致；有封面和無封面卡片都能維持閱讀順序。
- 少於 4 篇文章時不顯示手動廣告，避免短頁面廣告密度過高。

## 主要風險

### P1：側欄廣告斷點錯配

`AdSlot` 只在至少 1280px 初始化 `category_sidebar_desktop`，但 CSS 到 900px 以下才隱藏 `.category-sidebar`。因此 901–1279px 會顯示兩欄、保留矩形廣告高度與「AD」字樣，卻不可能載入廣告。

建議：分類側欄與共用桌面廣告初始化統一使用 1280px；1280px 以下改為單欄並完全移除側欄容器。

### P1：頂部廣告阻斷首屏內容

`category_after_intro` 位於分類說明和文章列表之間，雖設定為 banner，Google 的 responsive auto format 在本次畫面產生約 280px 高 iframe。加上上下間距後，A、C 的第一篇文章下降約一個完整首屏區段。

建議：分類頁取消 `category_after_intro`。若必須保留，應使用真正的 horizontal 廣告格式並驗證實際成品高度，不可用 CSS 裁切 Google 廣告。

### P2：同一首屏同時競爭多個廣告面

現行長分類可能同時啟用頂部、側欄、列表 inline、列表結尾與 Google bottom Anchor。即使每個版位單獨合理，組合後仍會壓過分類內容。

建議：同一時間最多保留一個首屏廣告面。啟用 bottom Anchor 時，不再顯示分類頂部廣告；桌面側欄可保留，但第一篇文章必須先進入首屏。

### P2：有廣告／無廣告頁高度差異過大

B 因文章少於 4 篇而不投放，首篇卡片緊接分類說明；A、C 則多出約 300–400px。使用者跨分類時會感覺頁面結構不一致。

建議：不需要把無廣告頁撐高；應縮小有廣告頁的阻塞空間，使第一篇卡片在三種狀態都保持接近的位置。

## 建議版位規劃

| 條件 | 建議版位 | 不建議 |
| --- | --- | --- |
| 1–3 篇文章 | 不顯示手動廣告 | 為填版面硬插廣告 |
| 4–9 篇、1280px 以下 | 第 3 或第 4 張卡片後 1 個 inline；若啟用 Anchor，二擇一 | 頂部大型廣告、側欄 |
| 4–9 篇、1280px 以上 | 右側 sticky 1 個；沒有側欄收益需求時改用列表 inline | 頂部加側欄同時出現 |
| 10 篇以上 | 每 6–8 張卡片 1 個 inline，最多 2 個；桌面可加 1 個 sticky | 固定每 10 張且不設總量上限 |
| 列表結尾 | 只有距最後一個 inline 足夠遠時才顯示 | 最後一張卡片後立刻再接廣告 |

推薦優先順序：`category_sidebar_desktop`（真正桌面）→ `category_inline` → `category_end`；停用 `category_after_intro`。Bottom Anchor 應視為首屏廣告面之一，避免和頂部版位同時啟用。

## 無障礙觀察

- 可確認的優點：主內容、文章列表、分類側欄、麵包屑與標題具有語意結構；廣告容器有「廣告」標籤。
- 風險：卡片封面、標題與「閱讀解答」各自連到同一篇文章，鍵盤使用者會遇到重複目的地的多個 Tab 停駐點。
- 風險：空廣告容器在視覺上只有低對比、小尺寸「AD」，容易被理解為載入失敗；斷點修正後應直接移除不可投放的容器。

## 驗證限制

本次以桌面 1229 × 1104 畫面、瀏覽器可存取樹與現有程式碼為依據。尚未測試 390px、768px、1280px 以上的實際 reflow，也未執行鍵盤逐項操作、螢幕閱讀器、廣告填充率或正式站 Core Web Vitals，因此不宣稱完整 WCAG 或收益表現。
