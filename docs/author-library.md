# 作者庫

最後更新：2026-09-05

## 使用方式

- 後台導覽的「作者庫」：依繁體中文、English、日本語及使用狀態篩選。
- 新增與編輯作者：作者名稱、網址代稱、富文字介紹。名稱最多 100 字，網址代稱最多 160 字，同語系不可重複，建立後語系固定。
- 編輯器的作者選單只列出文章語系的使用中作者。新增文章預設選取作者庫排序後的第一位，切換文章語系時也會改選該語系第一位；AI 改寫結果套用相同行為。
- 新文章必須選擇作者；歷史文章若沒有作者庫關聯，編輯時仍會保留原本帳號署名。選取作者後前台署名會連結到 `/{locale}/authors/{slug}`。
- 封存阻止新文章選取，不會刪除作者或既有署名；既有文章仍可保留其封存作者，也可換成其他作者。可隨時恢復使用。
- 作者頁顯示介紹與已發布文章，不包含草稿。封存作者的介紹頁仍可開啟。
- 修改作者網址代稱後，文章署名自動連到新網址；舊網址不提供轉址。
- OWNER 與 EDITOR 都可管理作者，需先完成登入與必要的密碼變更。

## 資料與遷移

新增 `Author`，文章新增可空的 `bylineId`；既有 `Post.authorId → User` 保留作為建立者紀錄。複合外鍵 `(bylineId, locale)` 在資料庫層防止跨語系關聯。儲存文章在 transaction 內鎖住作者，避免新指派與封存同時發生而繞過限制。

遷移 `20260905130000_author_library` 依既有文章的 `(authorId, locale)` 建立作者檔案，複製原署名並回填文章。介紹預設空白，管理者可自行補上。2026-09-05 已套用目前開發網站連線資料庫：原有 7 篇文章全部回填至同語系作者，文章內容保持原樣。

`Author` 啟用 RLS；透過有後台權限檢查的 Next.js Server Actions 與伺服器 Prisma 連線管理，不建立瀏覽器端資料庫寫入政策。介紹於儲存與顯示時清理 HTML。作者與文章頁 metadata / JSON-LD 使用所選作者，有已發布文章的作者頁加入 sitemap。

其他環境部署先執行 `npx prisma migrate deploy`，再執行 `npm run build`。Prisma schema 更新後，執行中的開發伺服器需要重啟以刷新 Prisma Client。

## 驗證紀錄

- 獨立本機測試資料庫：`onewiki_author_test`；沒有使用網站內容資料庫執行清空式測試。
- 全量 Vitest：76 個測試檔、284 個測試通過。
- TypeScript、ESLint、production build 通過。
- 新增整合測試覆蓋：作者語系隔離、同語系重複代稱、介紹 HTML 清理、修改名稱介紹、封存／恢復、既有文章保留封存作者、新指派拒絕封存或跨語系作者、登入驗證、作者頁排除草稿、未知語系／作者 404、sitemap。
- 元件測試覆蓋：作者選單隨語言切換清除選取、排除封存作者、署名連結的語言路徑與舊資料相容。
- 瀏覽器實測：新增暫存作者 → 修改介紹 → 封存 → 恢復 → 文章編輯器依語言篩選 → 儲存草稿並重開確認作者 → 從既有文章點擊署名開啟作者頁。
- 暫存作者與草稿已清除，既有 7 篇文章及作者關聯均保留。
