# Hierarchical Categories Design

最後更新：2026-09-05

## 目標

讓每個內容語系能獨立建立、編輯與瀏覽最多三級的分類樹。文章可直接歸屬任一層分類；父分類頁彙整自身與所有後代分類的已發布文章。

本次同時移除 `ai`、`software`、`social` 的特殊分類身分與專屬路由。所有分類使用相同資料規則及 canonical URL，不保留舊分類網址或轉址。

## 已確認決策

- 分類使用 `parentId` 自關聯。
- 分類最多三級。
- 每個語系的分類樹各自獨立管理。
- 文章可以放在一、二、三級中的任一層。
- 父分類頁顯示自身與所有後代分類的文章。
- 所有分類網址統一為 `/[locale]/category/[...slugs]`。
- 不保留 `/[locale]/ai`、`/[locale]/software`、`/[locale]/social`，也不建立相容轉址。
- 有文章或子分類的分類不可刪除。
- 一級分類可由後台設定是否顯示於頂部導覽及其排序。
- Phase 1 不保存分類路徑歷史，也不自動產生 301 轉址。

## 資料模型

在 `Category` 新增：

- `parentId String?`：空值表示一級分類。
- `parent Category?` 與 `children Category[]`：自關聯。
- `showInNavigation Boolean @default(false)`：只有一級分類可啟用。
- `sortOrder Int @default(0)`：同層排序；一級分類的導覽列也使用此值。

自關聯須同時使用 `parentId` 與 `locale` 連至現有的 `[id, locale]` 唯一鍵，讓資料庫阻止跨語系父子關係。父分類刪除採 `Restrict`。

保留 `@@unique([locale, slug])`。因此同一語系的 slug 全域唯一，即使分類位於不同父層也不能重複。這讓路徑產生、移動與後台查找保持明確；若未來確有同名 slug 需求，再另案改成同層唯一。

既有分類遷移規則：

- `parentId = null`
- 所有既有分類一律設為 `showInNavigation = true`；不依 slug 區分，管理者可在遷移後自行調整。
- 所有既有分類的 `sortOrder = 0`，相同排序值時依名稱排列。
- 現有文章的 `categoryId` 與內容資料不變。

## 分類規則

分類服務集中驗證以下條件：

1. 父分類存在且與子分類語系相同。
2. 分類最深只能到三級；三級分類不能成為其他分類的父層。
3. 分類不能以自己或自己的後代為父層。
4. 移動分類後，該分類及其最深後代仍不得超過三級。
5. `showInNavigation` 只能套用於一級分類；移至子層時自動設為 `false`。
6. 有直屬文章或直屬子分類時不可刪除。

建立、更新與移動在 transaction 內重新讀取並驗證關係，再寫入資料。分類名稱與說明可獨立修改；slug 或父層變更會改變自身及後代的公開網址，後台必須在送出前顯示警告。

## 網址與解析

所有分類 canonical URL 使用完整父鏈：

- 一級：`/zh-tw/category/ai`
- 二級：`/zh-tw/category/ai/chatgpt`
- 三級：`/zh-tw/category/ai/chatgpt/prompt-writing`

新增 catch-all route：`/[locale]/category/[...slugs]`。路由解析器從一級分類開始逐段驗證 `parentId`，不能只用最後一段 slug 找分類。不存在的 slug、錯誤的父子順序、超過三級或語系不符都回傳 404。

移除三個專屬分類 page route。所有分類連結必須透過單一 `getCategoryHref` helper 產生，不允許元件自行拼接或判斷固定 slug。

## 前台呈現

### 頂部導覽

讀取目前語系中 `parentId = null` 且 `showInNavigation = true` 的分類，依 `sortOrder`、名稱排序。導覽文字直接使用該語系的分類名稱，連結由 `getCategoryHref` 產生。

### 首頁

首頁只展示至少有一篇已發布後代文章的一級分類。卡片的文章數若顯示，應為自身與全部後代分類的已發布文章總數。

### 分類頁

分類頁包含：

1. 完整分類麵包屑。
2. 目前分類名稱與說明。
3. 依 `sortOrder`、名稱排序的直屬子分類卡片。
4. 目前分類及全部後代分類的已發布文章，依 `publishedAt desc` 排序。

每篇文章只屬於一個分類，因此父頁彙整不會產生重複文章。維持目前不分頁的行為；分頁不在本次範圍。

### 文章頁與 SEO

文章網址不變。文章麵包屑改為首頁、完整分類祖先鏈、文章標題。Category metadata、文章相關分類連結、Article Card、首頁、導覽列、sitemap 與結構化麵包屑都共用同一路徑 helper。

Sitemap 只收錄具有已發布文章的分類，並使用完整 canonical 階層網址。

## 後台分類管理

頁面先依內容語系篩選，且只顯示該語系的分類樹。

### 建立表單

- 名稱、slug、說明沿用現有欄位。
- 新增「上層分類」；空值建立一級分類。
- 父分類選項以縮排完整路徑顯示。
- 三級分類不列入可選父分類。
- 選擇一級時顯示「頂部導覽」與「排序」欄位；選擇父分類後隱藏並提交 `showInNavigation = false`。
- 從某列按「新增子分類」時，表單自動預選該分類。

### 樹狀列表

用縮排樹取代目前平鋪卡片。每列顯示：

- 名稱、層級與完整公開網址。
- 直屬文章數與包含後代的合計文章數。
- 一級分類的導覽顯示狀態與排序。
- 新增子分類、編輯、刪除操作。

有文章或子分類時停用刪除，並直接呈現原因。

### 編輯與移動

可修改名稱、slug、說明、父分類、排序及一級分類的導覽狀態。父分類選單排除自己、自己的後代，以及會使樹深超過三級的目標。伺服器仍須執行完整驗證，不信任前端限制。

## 文章與 AI 流程

文章新增、編輯、列表篩選、AI 文章生成與 AI 改寫所使用的分類選項，統一由分類樹 formatter 產生，例如：

```text
AI
— ChatGPT
—— Prompt 撰寫
軟體
— macOS
```

任一層都可被選取。既有的「文章語系必須與分類一致」驗證保留。提供給模型的分類名稱應包含完整分類路徑，降低同名或語意相近分類選錯的機率；模型仍只回傳既有 category ID。

## 錯誤與回饋

- 建立第四級：`分類最多只能有三級`。
- 跨語系父分類：`上層分類必須與目前分類使用相同語系`。
- 循環移動：`分類不能移到自己或自己的子分類下`。
- 移動後超過三級：`移動後的分類層級會超過三級`。
- 有文章：`分類仍有文章，無法刪除`。
- 有子分類：`分類仍有子分類，無法刪除`。
- 重複 slug：沿用 `網址代稱已被使用`。
- 無效公開路徑：404，不顯示內部錯誤。

後台成功訊息需區分建立、更新、移動與刪除。失敗時保留目前語系與操作上下文。

## 測試策略

### 資料庫與 repository

- 遷移前後分類與文章數量、關聯不變。
- 建立一至三級分類成功。
- 阻止第四級、跨語系、自己為父層與後代循環。
- 移動含後代的分類時正確計算最終深度。
- 有文章或子分類時禁止刪除。
- 取得祖先鏈、直屬子分類及全部後代 ID。
- 父分類查詢彙整自身和全部後代文章。

### 路由與 helper

- 一、二、三級 href 正確。
- 逐段解析正確父子鏈。
- 錯誤順序、缺少段落、超過三級與錯誤語系回傳 404。
- sitemap、metadata 與所有分類連結使用 canonical 階層網址。
- 舊的 `/[locale]/ai` 等網址不存在且不轉址。

### 後台與文章流程

- 語系切換只顯示對應分類樹。
- 建立表單限制父分類選項與導覽欄位。
- 樹狀列表正確顯示層級、網址與文章計數。
- 編輯、移動與刪除顯示正確成功或錯誤訊息。
- 文章編輯器、篩選器及 AI 流程顯示縮排分類路徑，且各層皆可選。

### 端對端

- 後台建立一、二、三級分類。
- 在各層建立文章並於父分類頁看到完整彙整。
- 導覽列只顯示被勾選的一級分類且排序正確。
- 完整麵包屑與三層分類導覽可操作。
- 頁面無 hydration、console 或無障礙名稱錯誤。

## 不在本次範圍

- 四級以上或無限層分類。
- 跨語系分類翻譯綁定。
- 分類舊網址、slug 歷史與 301 轉址。
- 一篇文章關聯多個分類。
- 分類頁分頁。
- 拖曳排序；本次使用數字排序欄位。

## 完成條件

1. 每個語系可獨立管理最多三級的分類樹。
2. 任一層可直接放文章，父分類頁會彙整全部後代文章。
3. 所有公開分類連結統一使用完整 `/category` 階層網址。
4. 舊專屬分類路由與固定 slug 邏輯完全移除。
5. 頂部導覽由後台設定的一級分類產生。
6. 建立、移動與刪除規則在伺服器端完整驗證。
7. 遷移不改變既有文章內容及分類關聯。
8. repository、路由、後台、前台、SEO 與端對端測試通過。
