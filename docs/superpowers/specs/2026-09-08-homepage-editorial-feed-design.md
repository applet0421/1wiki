# 1Wiki 首頁「極簡新文章流」重構設計

最後更新：2026-09-08

## 目標

首頁應讓首次到訪者立即看見全站最新的科技解法。內容優先順序為：閱讀型導言、統一權重的最新文章流、主題分類入口。此調整服務 AI、App、軟體、手機與 3C 的 How-To 和 Troubleshooting 內容；不改變文章發布排序或既有多語系資料來源。

## 已確認決策

- 首頁第一優先是「最新文章流」，不是主打單篇文章或先要求使用者挑選分類。
- 導言使用原主打文章的閱讀型標題尺度與行高，但不顯示主打文章卡。
- 首頁文章卡、文章清單、圖片比例、整卡點擊規則與響應式行為應與分類頁共用，不另外建立首頁卡片系統。
- 保留現有 12 篇首頁文章資料上限、根分類資料、翻譯字典與底部 Anchor 廣告行為。
- 首頁不顯示頂部廣告；文章流廣告位置與分類頁對齊：Inline、列表結尾與僅桌機側欄。
- Homepage Inline 廣告使用既有「分類頁每幾篇文章插入一則 Inline 廣告」後台設定；只有該篇後仍有文章時才顯示。
- 不新增資料表、欄位、後台間隔設定或首頁文章載入 API。

## 資訊架構

1. **閱讀型導言**：保留首頁價值主張與一段說明，H1 使用原主打文章的字級節奏；縮短垂直空白，使文章流在初始視窗可見。
2. **最新文章流**：所有文章依既有 repository 回傳順序（最新優先）顯示，並以分類頁的 `CategoryArticleList` 與 `ArticleCard` 呈現。首頁不分離第一篇文章，也不賦予任何一篇更高視覺權重。
3. **主題捷徑**：根分類卡片作為文章流後的延伸探索入口。
4. **廣告**：在文章數至少四篇時，顯示分類頁同等條件的 Inline、結尾及桌機側欄廣告；頂部不顯示廣告。

## 響應式行為

| 視窗 | 導言 | 最新文章流 | 廣告與分類捷徑 |
| --- | --- | --- | --- |
| ≥1280px | 主打文章同尺度的 H1，但維持緊湊高度 | 分類頁的寬幅橫向卡片、4:3 封面 | 顯示 Sticky 側欄；分類捷徑多欄 |
| 901–1279px | 單欄內容軸 | 分類頁相同橫向列式 | 側欄隱藏；分類捷徑兩欄 |
| 641–900px | 縮小間距與標題 | 分類頁相同橫向卡片、4:3 封面 | 側欄隱藏；分類捷徑兩欄 |
| ≤640px | 文章流在首屏開始 | 分類頁相同直向卡片、16:9 封面 | 側欄隱藏；分類捷徑單欄 |

## 元件與資料流

- `HomePage` 從既有 `getHomeData(locale)` 取得 `posts` 和 `categories`，並將全部 `posts` 作為首頁文章流輸入。
- 首頁採用可共用的文章流元件，該元件應接受初始文章、locale、dictionary、Inline placement 與既有 `categoryInlineAdInterval`；首頁不需要 category API 的無限載入參數。
- `ArticleCard` 與分類頁共用，首頁不新增任何首頁專屬卡片變體或圖片比例規則。
- `HomePage` 使用首頁路徑作為廣告 context，並取得 `home_inline`、`home_end`、`home_sidebar_desktop` placement；各 placement 的顯示門檻與分類頁一致。
- `dictionary.home` 只補足導言、最新文章流與主題捷徑所需的多語系文案；不在元件內硬編使用者可見文案。
- `AdsenseScript` 與 `getAnchorAdsConfig` 維持原有首頁 Anchor 設定流程。

## 互動與可近用性

- 最新文章與主題捷徑均維持可鍵盤操作的真實連結。
- 首頁文章卡的整卡點擊、封面、標題與 CTA 行為必須與分類頁一致，且不建立巢狀連結。
- 標題、摘要與日期保留清晰的層級；截斷只用於列表密度，不能隱藏唯一的文章辨識資訊。
- 在小螢幕避免 Hover-only 資訊或依賴側欄。

## 驗證

- 擴充首頁與文章流單元測試，驗證全部首頁文章按既有順序出現在分類頁同款清單、Inline 條件符合後台間隔、側欄／結尾門檻正確，以及沒有文章時的空狀態不變。
- 執行首頁、首頁文章流、ArticleCard 與 CategoryArticleList 相關 Vitest 測試，並執行 `git diff --check`。
- 以 375px、768px、1024px、1440px 與寬螢幕實際檢視首頁，確認無水平捲動、首頁文章卡與分類頁外觀一致、圖片比例正確、廣告斷點正確，以及分類入口沒有搶先於文章。
- 現有全域 lint 已知存在與本工作無關的 `src/lib/wechat-import/browser-extractor.ts` 問題；除非該問題獲修正，不將全域 lint 視為本次首頁變更的驗證結果。
