# 1Wiki 首頁「主打解法＋最新列表」重構設計

最後更新：2026-09-08

## 目標

首頁應讓首次到訪者立即看見可閱讀的、最新的科技解法。內容優先順序為：最新主打文章、後續最新文章、主題分類入口。此調整服務 AI、App、軟體、手機與 3C 的 How-To 和 Troubleshooting 內容；不改變文章發布排序或既有多語系資料來源。

## 已確認決策

- 首頁第一優先是「最新、最值得先看的解法文章」，不是先要求使用者挑選分類。
- 採用「主打解法＋最新列表」方向。
- 保留現有 12 篇首頁文章資料上限、根分類資料、翻譯字典與底部 Anchor 廣告行為。
- 首頁不新增頂部、側欄或 Inline 廣告位。
- 不新增資料表、欄位、後台設定或 API。

## 資訊架構

1. **精簡首頁導言**：保留首頁價值主張與一段說明，縮短垂直空白，使文章內容在初始視窗可見。
2. **主打解法**：使用發布時間最新的第一篇文章。顯示分類、4:3 封面、標題、摘要、日期與閱讀連結；整張卡片具文章連結的可點擊區。
3. **最新列表**：使用剩餘文章，提供一致但低於主打文章的視覺權重。文章維持按目前 repository 回傳順序顯示。
4. **主題捷徑**：根分類卡片改為較輕量的探索區，位於文章內容後面。

## 響應式行為

| 901–1279px | 單欄內容軸；主打維持橫向 4:3 封面 | 橫向列式，避免產生側欄 | 兩欄捷徑 |

| ≤640px | 導言與主打垂直堆疊；封面 16:9 | 一列一篇、封面置頂、標題與摘要優先可讀 | 單欄捷徑 |

## 元件與資料流

- `HomePage` 從既有 `getHomeData(locale)` 取得 `posts` 和 `categories`。
- `posts[0]` 供主打解法區；`posts.slice(1)` 供最新列表。沒有首篇文章時仍使用既有空狀態。
- 既有 `ArticleCard` 繼續提供文章列，必要時擴充可區分首頁主打與首頁列表的語意 class 或變體；分類頁的卡片行為不可回歸。
- `dictionary.home` 補足主打區、最新列表與分類捷徑所需的多語系文案；不在元件內硬編使用者可見文案。
- `AdsenseScript` 與 `getAnchorAdsConfig` 維持原有首頁設定流程，不調整廣告資料。

## 互動與可近用性

- 主打文章、最新文章與主題捷徑均維持可鍵盤操作的真實連結。
- 整張文章卡片可點擊，但封面、標題、CTA 不建立巢狀連結。
- 標題、摘要與日期保留清晰的層級；截斷只用於列表密度，不能隱藏唯一的文章辨識資訊。
- 在小螢幕避免 Hover-only 資訊或依賴側欄。

## 驗證

- 擴充首頁單元測試，驗證首篇文章與剩餘列表被分別渲染、分類出現在文章區之後，以及沒有文章時的空狀態不變。
- 執行首頁與 ArticleCard 相關 Vitest 測試，並執行 `git diff --check`。
- 以 375px、768px、1024px、1440px 與寬螢幕實際檢視首頁，確認無水平捲動、首篇卡片與列表層級清楚、圖片比例正確，以及分類入口沒有搶先於文章。
